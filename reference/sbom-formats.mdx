---
title: "SBOM formats"
description: "All SBOM output formats supported by Syft and how to use them."
---

Syft can produce SBOMs in multiple industry-standard and tool-native formats. Specify the output format with the `-o` flag.

```bash
syft <source> -o <format>
```

To pin a specific version of a versioned format, append `@<version>`:

```bash
syft alpine:latest -o spdx-json@2.2
```

---

## Format reference

<AccordionGroup>

<Accordion title="syft-json">

| | |
|---|---|
| **Format ID** | `syft-json` |
| **Description** | Syft's native JSON format. The most complete representation of Syft's cataloging output, including all package metadata, file details, relationships, and distro information. Use this format when you want maximum fidelity or plan to feed the SBOM into other Anchore tools. |
| **Versions** | Single version, tracked by the schema version embedded in the document (currently `16.1.3`) |
| **Schema** | `https://raw.githubusercontent.com/anchore/syft/main/schema/json/schema-latest.json` |

```bash
syft alpine:latest -o syft-json
syft alpine:latest -o syft-json=sbom.json
```

</Accordion>

<Accordion title="cyclonedx-json">

| | |
|---|---|
| **Format ID** | `cyclonedx-json` |
| **Description** | [CycloneDX](https://cyclonedx.org/) BOM in JSON encoding. A widely adopted SBOM standard with strong supply-chain security tooling support. |
| **Supported versions** | `1.2`, `1.3`, `1.4`, `1.5`, `1.6` |
| **Default version** | `1.6` |

```bash
# Latest supported version (1.6)
syft alpine:latest -o cyclonedx-json

# Specific version
syft alpine:latest -o cyclonedx-json@1.4

# Write to file
syft alpine:latest -o cyclonedx-json=sbom.cdx.json
```

<Note>
CycloneDX JSON is not supported for versions below 1.2. Use `cyclonedx-xml` if you require 1.0 or 1.1.
</Note>

</Accordion>

<Accordion title="cyclonedx-xml">

| | |
|---|---|
| **Format ID** | `cyclonedx-xml` |
| **Aliases** | `cyclonedx`, `cyclone`, `cdx` |
| **Description** | [CycloneDX](https://cyclonedx.org/) BOM in XML encoding. Supports the full CycloneDX version range including legacy versions 1.0 and 1.1. |
| **Supported versions** | `1.0`, `1.1`, `1.2`, `1.3`, `1.4`, `1.5`, `1.6` |
| **Default version** | `1.6` |

```bash
# Latest supported version (1.6)
syft alpine:latest -o cyclonedx-xml

# Using the short alias
syft alpine:latest -o cyclonedx

# Legacy version
syft alpine:latest -o cyclonedx-xml@1.1

# Write to file
syft alpine:latest -o cyclonedx-xml=sbom.cdx.xml
```

</Accordion>

<Accordion title="spdx-json">

| | |
|---|---|
| **Format ID** | `spdx-json` |
| **Description** | [SPDX](https://spdx.dev/) Software Package Data Exchange in JSON encoding. A widely used open standard for communicating software bill of materials information. |
| **Supported versions** | `2.2`, `2.3` |
| **Default version** | `2.3` |

```bash
# Default version (2.3)
syft alpine:latest -o spdx-json

# Older version
syft alpine:latest -o spdx-json@2.2

# Write to file
syft alpine:latest -o spdx-json=sbom.spdx.json
```

<Note>
SPDX JSON does not support version 2.1. Use `spdx-tag-value` if you require SPDX 2.1.
</Note>

</Accordion>

<Accordion title="spdx-tag-value">

| | |
|---|---|
| **Format ID** | `spdx-tag-value` |
| **Aliases** | `spdx`, `spdx-tv` |
| **Description** | [SPDX](https://spdx.dev/) in the tag-value text encoding. Human-readable line-based format, the original SPDX serialization. |
| **Supported versions** | `2.1`, `2.2`, `2.3` |
| **Default version** | `2.3` |

```bash
# Default version (2.3)
syft alpine:latest -o spdx-tag-value

# Using the short alias
syft alpine:latest -o spdx

# Specific version
syft alpine:latest -o spdx-tag-value@2.1

# Write to file
syft alpine:latest -o spdx-tag-value=sbom.spdx
```

</Accordion>

<Accordion title="github-json">

| | |
|---|---|
| **Format ID** | `github-json` |
| **Description** | GitHub Dependency Graph submission format. Use this when uploading SBOMs to the [GitHub Dependency Submission API](https://docs.github.com/en/rest/dependency-graph/dependency-submission). |
| **Versions** | Single version |

```bash
syft alpine:latest -o github-json
syft alpine:latest -o github-json=sbom.github.json
```

</Accordion>

<Accordion title="purls">

| | |
|---|---|
| **Format ID** | `purls` |
| **Description** | A plain-text list of [Package URLs (purls)](https://github.com/package-url/purl-spec), one per line. Useful for quick lookups or feeding into vulnerability scanners that accept purl lists. |
| **Versions** | Single version |

```bash
syft alpine:latest -o purls
```

</Accordion>

<Accordion title="table">

| | |
|---|---|
| **Format ID** | `table` |
| **Description** | Human-readable ASCII table printed to stdout. The default output format. Shows package name, version, type, and location. Not machine-parseable; use `syft-json` or a standards format for automation. |
| **Versions** | Single version |

```bash
# table is the default
syft alpine:latest
syft alpine:latest -o table
```

</Accordion>

<Accordion title="text">

| | |
|---|---|
| **Format ID** | `text` |
| **Description** | A simple newline-delimited text list of `name version type` entries. Lighter than `table` and easier to pipe through shell tools. |
| **Versions** | Single version |

```bash
syft alpine:latest -o text
```

</Accordion>

<Accordion title="template">

| | |
|---|---|
| **Format ID** | `template` |
| **Description** | Render the SBOM using a custom [Go text/template](https://pkg.go.dev/text/template) file. Gives you full control over the output structure. Requires the `-t` / `--template` flag pointing to a template file. |
| **Versions** | Single version |

```bash
syft alpine:latest -o template -t my_format.tmpl
```

Your template receives the full `sbom.SBOM` Go struct. A minimal example template:

```text my_format.tmpl
{{- range .Artifacts -}}
{{ .Name }} {{ .Version }}
{{ end -}}
```

<Note>
The `template` format is not available with `syft attest`.
</Note>

</Accordion>

</AccordionGroup>

## Multiple outputs at once

You can specify `-o` multiple times to produce several outputs from a single scan. Use the `<format>=<file>` syntax to direct each output to its own file. Omitting a file path sends that output to stdout.

```bash
# Write syft-json to a file and print spdx-json to stdout
syft alpine:latest \
  -o syft-json=sbom.json \
  -o spdx-json

# Write three formats at once
syft alpine:latest \
  -o syft-json=sbom.syft.json \
  -o cyclonedx-json=sbom.cdx.json \
  -o spdx-tag-value=sbom.spdx
```

---

## Saving output to a file

Any format can be written to a file by appending `=<path>` to the format ID:

```bash
syft alpine:latest -o cyclonedx-json=./sbom.cdx.json
```

This is equivalent to redirecting stdout, but works correctly even when Syft also prints progress output to stderr.

---

## Converting between formats

Use `syft convert` to translate an existing SBOM file from one format to another without re-scanning:

```bash
syft convert sbom.syft.json -o spdx-json=sbom.spdx.json
syft convert sbom.syft.json -o cyclonedx-xml@1.4=sbom.cdx.xml
```

<Warning>
`syft convert` is experimental. Some fields may not round-trip perfectly between formats due to schema differences. See the [format conversion notes](https://github.com/anchore/syft/wiki/format-conversion) for details.
</Warning>
